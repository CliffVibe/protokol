## Как мерили и что пошло не по плану (для отчёта жюри)
- План: `lighthouse_audit` из chrome-devtools-mcp 1.12.0 (решение 07-tooling: `@lhci/cli` отклонён). Подключён `claude mcp add … -s local`; в этой сессии инструменты не появились (сервер подхватывается при старте сессии), поэтому использовали его командную строку `chrome-devtools` — те же инструменты, флаги `--isolated --headless --no-usage-statistics --no-performance-crux`.
- **Chromium от Playwright (`chromium-1248`, 437 МБ) Windows не дал запустить** (`Permission denied` — похоже, Smart App Control). Обходить защиту ОС не стали: запускали `chrome-headless-shell` из того же набора Playwright (его Windows пропускает, на нём же идут e2e).
- **`lighthouse_audit` chrome-devtools-mcp не считает Performance**: категории в коде инструмента зашиты (`accessibility, seo, best-practices, agentic-browsing`), а встроенная сборка Lighthouse содержит из метрик производительности только CLS. Первый «Performance 100» через неё оказался ненастоящим (ни FCP, ни LCP, ни TBT) — заметили по пустым метрикам и не засчитали.
- Для честной оценки — **полный `lighthouse@13.6.0`** (Google, Apache-2.0, provenance SLSA, релиз 27.10 — старше 3 дней, `npm audit` 0 на 138 зависимостей, install-скриптов нет), поставлен **вне проекта** — во временную папку агента (181 МБ), не зависимость `package.json`; отправка ошибок Sentry выключена (`enableErrorReporting: false`). После этапа папка удаляется.
- Accessibility из `lighthouse_audit` chrome-devtools-mcp (снят первым) — тоже 100 на «Сейчас»: совпадает с полным Lighthouse.
