### 05.11 — Вход Claude Code в проект, окружение, разбор каркаса, T01 (локальная часть)
**Инструмент:** Claude Code (Opus 5.5) в десктоп-приложении Claude, нативный Windows 11; субагент `ux-reviewer`; встроенный браузер приложения для проверки на 390px.
**Задача (промпт):** первое сообщение из `00-first-message.md` — пять шагов по одному с одобрением человека: прочитать каркас → проверить окружение («ничего не устанавливай сам») → git → «критический взгляд — до кода», не больше 7 пунктов → план T01 в plan mode. По ходу человек расширил полномочия: > «Установи всё нужное сам, так, чтобы потом можно было легко удалить (если занимает много места… уточни, сколько места займёт)».
**Что сделал ИИ:**
- Окружение: таблица «есть / не хватает». Поставил pnpm 11.28.10, TypeScript 6.0.3 и typescript-language-server (~50 МБ), обновил Claude Code до 2.1.318. Для тяжёлого — Docker Desktop (3,2 ГБ) — сначала дал выбор с размерами и способом удаления; поставил после выбора. Выяснил, что таймаут shadcn MCP — холодный кэш npx, а не Windows-обёртка (правку `.mcp.json` не понадобилось).
- Git: `git init -b main`, локальная идентичность с noreply-адресом GitHub (личная почта не попадёт в публичную историю), `core.autocrlf=input`; первый коммит каркаса.
- Критический разбор (7 пунктов, все приняты): `next@16.4.5` моложе `minimumReleaseAge` → старт на 16.4.4; CI каркаса не мог стать зелёным (Prisma-шаги до T02, устаревшие actions на тегах); проверка роли в layout не защищает (подтверждено локальной документацией Next 16); жюри «ломает» общее демо → ночной пересев и «Войти как…»; противоречия в настройках агента (`deny` закрывал `.env.example`, открыт `browser_run_code_unsafe`); риски прода в РФ (Docker Hub, OOM при сборке на 2 ГБ, TLS GigaChat, кириллица в PDF); усилители по критериям жюри.
- Документы: правки по ревью в CLAUDE.md, 01–03, 06, задачах T01–T14; исходное ТЗ положено в `docs/00-brief.md` + `.docx`; дедлайн 22.11 и решения человека — в `02-plan.md`.
- T01 локально: скелет Next 16.4.4 + shadcn (переменные shadcn направлены на наши токены), ESLint-запрет `@/server/db` вне `repos/`, Vitest + Playwright (desktop, mobile-360, axe) против standalone-сборки, Dockerfile (не root, healthcheck), compose dev/prod, Caddy с HSTS, CI с actions по SHA, сборка образа в GHCR. Итог: lint, typecheck, unit 2/2, e2e 8/8, образ 299 МБ здоров.
**Проблемы и исправления:**
- Защита цепочки поставок сработала пять раз (таблица в `07-tooling.md`): `next@16.4.5` и `semver@6.3.2` слишком свежие; `undici-types@6.21.0` без provenance → вместо ослабления политики перешли на Node 24; ESLint 10 несовместим с плагинами Next → ESLint 9; `pnpm dlx shadcn` собрал несовместимые зависимости → `npx shadcn@4.23.0`.

- `shadcn init` перезаписал наш токен `--muted`, подменил шрифты на Geist и добавил пакет `cn` — откатили к 04-design, `cn` проверили (официальный, MIT).
- Ошибки самого ИИ (4) — в `ai-errors.md`: слишком широкий `prettier --write .` по каркасу; невалидный YAML в `image.yml`; `^` в версиях вопреки правилу; попытка самостоятельно править права агента.

### 06.11 — T02. Схема БД и сид (параллельно с T04 в отдельной сессии)
**Инструмент:** Claude Code (Opus 5.5); субагенты `web-fetch` (официальная документация Prisma 7), `security-reviewer`; параллельная сессия Claude Code для T04 в своей ветке.
**Задача (промпт):** > «T02 здесь, T04 отдельно» — после предложения вести дизайн-систему параллельно в отдельной сессии. План T02 — в plan mode, одобрен человеком.
**Что сделал ИИ:**
- Сверил Prisma 7 по prisma.io (не по памяти): генератор `prisma-client` с `output`, URL в `prisma.config.ts`, обязательный драйвер-адаптер `@prisma/adapter-pg`, ESM, ручной `generate` и сид.
- `prisma/schema.prisma` по эскизу 03 + связи; дополнения записаны в 03 (`Grade.teacherId`, `Request.seq`, `CANCELLED`). Две миграции.
- `src/server/db.ts` (синглтон, `server-only`), `repos/system.ts` → `/api/health` с проверкой БД (503 при падении).
- `hashPassword/verifyPassword` на argon2id (OWASP) — общий для сида и будущего входа.
- `buildSeed(now)` — детерминированная чистая функция: 8 факультетов, 10 групп, 716 пар на 5 недель, переносы/отмены по 06, Алиса/Тимур/Вера/Ирина + 5 фоновых студентов для очереди сотрудника. «Сегодня» всегда учебный день, ничего не датировано будущим. Пароли только из `SEED_PASSWORD_*`, токены .ics и QR — `crypto.randomBytes`.
- Тесты: 41 юнит (детерминизм; будни, суббота, воскресенье, 04:00) + 7 интеграционных на PostgreSQL (argon2id в БД, видимость факультетов для Ирины, токены, seq, `reset-demo`).
- Прод: образ `:tools` (Prisma CLI + tsx) для миграций и ночного пересева демо по cron; standalone-образ проверен с реальной БД.
**Проблемы и исправления:**
- `trustPolicy` отклонил `prisma@7.10.1`: CLI 7.10.x опубликован токеном без provenance, а соседние версии — через GitHub Actions с SLSA. ИИ собрал доказательства и предложил выбор; **человек выбрал 7.9.0 целиком** — политику не ослабляли.
- Prisma 7 сам заблокировал `migrate reset` от ИИ-агента и потребовал согласия человека. ИИ не стал сбрасывать базу, а проверил «с нуля» на временной пустой базе.
- ESLint и `tsc` зашли в рабочую копию параллельной сессии (`.claude/worktrees`) — исключили `.claude/`.
- `security-reviewer`: блокеров нет; 4 правки внесены сразу (динамический `import()` Prisma, общий пароль базы в CI для e2e, 128 бит у QR-токенов, минимальная длина паролей, `CANCELLED` + запрет каскада для выданной справки), остальное разложено по T03/T08/T09/T13/T14. Ошибки ИИ — в `ai-errors.md` (3 записи).
**Вручную:** решение по версии Prisma (7.9.0); решение «T04 в отдельной сессии». Ждёт человека: создать `.env` из `.env.example` с паролями жюри; одобрить правку `/deploy` под образ `:tools`.
