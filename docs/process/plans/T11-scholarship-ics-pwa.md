# T11. «Что если…», календарь (.ics), PWA — план

## Контекст
Последние две «смелые идеи» до ИИ (01-concept F и G): превратить таблицу оценок в ответ «если сдам экономику на 4 — стипендия сохранится?» и дать расписанию жить там, где студент уже смотрит (свой календарь, телефон без сети). Сейчас: правило стипендии — `src/server/services/academics.ts`; `Student.calendarToken` (32 байта) есть в сиде, `proxy.ts` пропускает `/api/calendar/` без входа, маршрута нет; профиль — заглушка; в `public/` только `robots.txt`.

Решения человека (07.11): security-guidance **остаётся выключенным**; «Что если» — **итог сессии → прогноз**; профиль — **календарь + данные + «Выйти на всех устройствах»**; офлайн — **только расписание**.

Зависимостей **не добавляю**: .ics — свой генератор текста, service worker — свой файл, PNG-значки — один раз рендерю из `icon.svg` Chromium-ом проекта (Playwright уже стоит).

## Шаг 1. «Что если…» на `/grades`
**Правило — одна чистая функция для сервера и клиента.**
- Новый `src/lib/scholarship.ts` (без БД и `server-only`; только `import type` из Prisma): переезжают `GradeRow`, `SCHOLARSHIP_MIN_RATING/MARK`, `isDebt`, и новое ядро `scholarshipAsOf(grades, semester): Scholarship` — правило «нет долгов в прошлых семестрах, в прошлой сессии нет оценок ниже 4, в семестре `semester` рейтинг ≥ 60». `services/academics.ts` импортирует его (`summarizeStudy` = `scholarshipAsOf(grades, current)`), реэкспортирует типы/константы — существующие импорты не ломаются, текст причин тот же.
- `projectSession(grades, picks)` там же: строки текущего семестра получают выбранный итог (`finalMark` 5/4/3/2 или `passed`), невыбранные без итога считаем сданными «не ниже 4» (явно в тексте), → `scholarshipAsOf(simulated, current + 1)` (рейтингов следующего семестра ещё нет — условие 3 не срабатывает). Плюс `sessionAverage` — средний балл по пятибалльным итогам сессии (известные + выбранные), `null`, если их нет.
- Юнит-тесты: прежние тесты `summarizeStudy` зелёные без правок (положительный контроль переноса); прогноз: Алисин случай «экзамен на 3 → не сохранится, причина „Оценка 3 в прошлой сессии: …“», «незачёт → долг», старый долг Тимура → «не сохранится» при любых выборах, ничего не выбрано → «сохранится (если остальные на 4 и выше)».

**Интерфейс** — `src/components/grades/what-if.tsx` (`"use client"`), секция `#what-if` под списком дисциплин, только при выбранном текущем семестре и наличии дисциплин без итога (у Алисы 6, у Тимура 4):
- Заголовок «Что если…» + строка «Выберите, как планируете сдать. Ничего не сохраняется — это только прикидка».
- Строка дисциплины: название, форма контроля, текущий рейтинг; выбор — нативные радио-кнопки сегментом (`fieldset`/`legend`, цели 44 px): экзамен/дифзачёт/курсовая — «5 4 3 2», зачёт — «Зачтено / Не зачтено»; без выбора — «не выбрано».
- Итог (`role="status"`, `aria-live="polite"`): `ScholarshipBadge` с подписью «После сессии стипендия сохранится / под угрозой» + причины, «Средний балл сессии: 4,5», «Не выбрано: 3 — считаем, что сдадите на 4 и выше». На телефоне итог — `sticky` над нижней навигацией внутри секции (видно, пока выбираешь); на ≥1024 — обычный блок над строками. Кнопка «Сбросить» — ghost (заливных нет).
- В «Как у меня дела» под значком стипендии — ссылка «Что если сдать сессию…» → `#what-if`.
- `ScholarshipBadge` получает необязательные подписи (`keptLabel/threatLabel`), вид прежний.

## Шаг 2. Подписка `.ics`
- **Репозиторий** `src/server/repos/calendar.ts` — второе исключение «без ctx» после `verify.ts` (дописать в CLAUDE.md «Структура» и 03-architecture): `lessonsByCalendarToken(token, from, to)` — `findUnique({ calendarToken })` с select только `groupId` и id языковых групп, затем пары этих групп; наружу — только поля пары (время, дисциплина, вид, корпус, аудитория, преподаватель (вымышленный), изменение/причина). Ни ФИО, ни группы, ни зачётки, ни оценок.
- **Генератор** `src/lib/ics.ts` (чистый): VCALENDAR (`PRODID`, `METHOD:PUBLISH`, `X-WR-CALNAME:Протокол — расписание`, `X-WR-TIMEZONE:Europe/Moscow`, `REFRESH-INTERVAL`/`X-PUBLISHED-TTL` 6 ч); VEVENT: `UID:<lesson.id>@protokol`, `DTSTAMP`, `DTSTART/DTEND` в UTC (`…Z`), `SUMMARY` «Микроэкономика — лекция», `LOCATION` «корпус, ауд. …», `DESCRIPTION` преподаватель + причина изменения; отменённая — `STATUS:CANCELLED` и «Отменена:» в названии, перенесённая — «было …». Экранирование `\ ; , \n`, CRLF, складывание строк по 75 **байтам UTF-8** (кириллица — 2 байта, не рвать символ). Подписи видов — `LESSON_KIND` из `components/now/labels.ts` (вынесу в `lib`, если тянет клиентский код).
- **Маршрут** `src/app/api/calendar/[token]/route.ts` GET: отрезать `.ics` → zod `^[A-Za-z0-9_-]{43}$` (32 байта base64url) → репозиторий; битый/неизвестный → **404 без тела** (без запроса к БД для битого). Окно: −14 … +90 дней. Заголовки: `text/calendar; charset=utf-8`, `Content-Disposition: inline; filename="protokol.ics"`, `Cache-Control: private, no-store`, `X-Robots-Tag: noindex`. В белый список `tests/unit/guards.test.ts` (`PUBLIC_ROUTES`) с причиной «подписка по токену 256 бит, только пары (S7)».
- **Перевыпуск** — `src/server/actions/profile.ts`: `rotateCalendarToken` — `requireStudent()` первой строкой, новый токен `randomBytes(32).base64url`, `repos/profile.rotateCalendarToken(ctx, token)` = `updateMany({ where: { id: ctx.studentId } })`, `count === 1`, `revalidatePath("/profile")`. Ввода нет — zod не нужен (ID только из ctx).

## Шаг 3. Профиль `/profile`
- `repos/profile.profileOf(ctx)` — явный select: ФИО, факультет, программа, курс, группа, языковые группы, `calendarToken` (без зачётки). Ссылка `APP_URL/api/calendar/<token>.ics` собирается на сервере (`src/server/app-url.ts`).
- Блоки: **«Мои данные»** (список `dl`); **«Расписание в календаре»** — «Добавить в Google Календарь» (`calendar.google.com/calendar/render?cid=<webcal-ссылка>`, это же путь для Android), «Добавить на iPhone» (`webcal://…`), «Скопировать ссылку» (клиентский островок, `navigator.clipboard`, сообщение «Ссылка скопирована» в `role="status"`), `<details>` «Как подписаться» — шаги для iOS, Android, Google на компьютере; сноска «Ссылка личная: по ней видно ваше расписание. Если отправили её кому-то — перевыпустите»; **«Перевыпустить ссылку»** — outline + `DialogForm` («Старая ссылка перестанет работать, календари на ней перестанут обновляться. Подписаться нужно будет заново»). **«Безопасность»** — «Выйти на всех устройствах» через `DialogForm` → существующий `logoutEverywhere`.
- Одна заливная кнопка на экран — «Добавить в Google Календарь»; остальные outline/ghost. Состояния: `loading.tsx` есть; ошибка — `error.tsx` (добавлю, как у расписания).
- На dev-адресе (localhost) Google ссылку не прочитает — под кнопками тихая строка «Подписка заработает на опубликованном сайте», только когда `APP_URL` не https.

## Шаг 4. PWA
- **Значки**: скрипт `scripts/render-icons.mjs` (Chromium проекта, светлый вариант «Листа бланка») → `public/icons/icon-192.png`, `icon-512.png`, `maskable-512.png` (поле 20 %, фон `--bg`), `src/app/apple-icon.png` 180 px (Next сам ставит `<link rel="apple-touch-icon">`). PNG коммитим, скрипт — для пересборки.
- **Манифест** `src/app/manifest.ts` → `/manifest.webmanifest`: «Протокол — цифровой деканат», `short_name` «Протокол», `start_url: "/"`, `display: standalone`, `lang: ru`, цвета из токенов «Бланк», значки выше + `icon.svg`.
- **Service worker** `public/sw.js` (версия в имени кэша, старые чистит в `activate`, `clients.claim()`):
  - `/_next/static/*` — cache-first (имена с хешем), не больше 150 записей;
  - навигация на `/schedule…` — network-first: успешный ответ кладётся в кэш страниц; без сети — из кэша; голый `/schedule` без сети ищет `?day=<сегодня по Москве>`, затем последний сохранённый `/schedule`;
  - прочая навигация без сети — `public/offline.html` (+ `offline.css`, без inline-стилей): «Нет сети. Расписание на две недели сохранено» + ссылка «Открыть расписание»;
  - сообщение `cache-schedule` со списком адресов → по очереди докачивает их (не чаще раза в 6 ч); сообщение `clear` → стирает кэш страниц.
- **Регистрация** `src/components/pwa/register-sw.tsx` (`"use client"`, только `NODE_ENV === "production"`) в оболочке студента; после регистрации отдаёт воркеру уже загруженные `/_next/static/*` (из `performance.getEntriesByType("resource")`) — иначе первый визит не сохранил бы CSS.
- **Две недели**: страница расписания рендерит `<OfflineSchedule urls renderedAt>` — сервер считает адреса существующими `dayHref/weekHref`: `/schedule`, 14 дней `?day=…` текущей и следующей недели, `?week=` текущей и следующей. Без дублирования календарной логики в воркере.
- **Офлайн-тост** `src/components/pwa/offline-notice.tsx`: `navigator.onLine` + события `online/offline`; на расписании — «Нет сети — показываем сохранённое расписание (обновлено 7 ноября, 14:05)» (время из `renderedAt`, кэш HTML его хранит); на прочих — «Нет сети — без интернета доступно только расписание». Плашка над нижней навигацией, `role="status"`, иконка `WifiOff` + текст (не только цвет).
- **Выход стирает кэш страниц** (общий компьютер): `LogoutButton` и «Выйти на всех устройствах» перед отправкой шлют `clear` / `caches.delete`; воркер дополнительно стирает кэш при навигации на `/login`. Офлайн чужое расписание не открыть.
- **CSP и proxy** (проверено заранее): в `script-src` стоит `'strict-dynamic'` — при нём `'self'` для воркера **не действует**, регистрация упала бы. Добавляю в `buildCsp` `worker-src 'self'` и `manifest-src 'self'` (+ тест в `tests/unit/auth-pure.test.ts`). В `matcher` proxy исключаю `sw.js`, `manifest.webmanifest`, `icons/`, `apple-icon.png`, `offline.html`, `offline.css` — иначе без cookie их уводит на `/login`. `next.config.ts`: для `/sw.js` — `Cache-Control: no-cache` (обновления воркера доходят сразу).
- **e2e не задевает воркер**: в `playwright.config.ts` `serviceWorkers: "block"` для всех проектов, `"allow"` — только в `pwa.spec.ts` (иначе каждый тест расписания докачивал бы 17 страниц).

## Шаг 5. Тесты
- **Юнит**: `scholarship` (выше); `ics` — экранирование, складывание по байтам (строка с кириллицей ≤ 75 байт, склейка обратно даёт исходник), CRLF, отменённая → `STATUS:CANCELLED`; разбор токена (`.ics` отрезан, 42/44 символа, мусор → отказ); `buildCsp` содержит `worker-src 'self'`; guards-страж знает новый маршрут.
- **Интеграция (БД)**: `lessonsByCalendarToken` — чужой/неизвестный токен → null; выборка Алисы содержит пары её языковой группы и не содержит пар чужой группы; `rotateCalendarToken` меняет только свой токен.
- **e2e** `tests/e2e/calendar.spec.ts` (в исключения eslint, `--repeat-each=3`):
  - аноним: `.ics` Алисы (токен из БД) → 200, `text/calendar`, есть `BEGIN:VEVENT` и название её дисциплины (положительный контроль), **нет** её фамилии, зачётки, группы, оценок; токен Тимура → его пары, без пар только Алисиной группы (изоляция); битый/неизвестный → 404 с пустым телом;
  - **перевыпуск ломает старую ссылку** (приёмка 3): временный студент (`helpers/temp-student.ts`) → старый токен 200 → «Перевыпустить ссылку» в профиле → старый 404, новый (из профиля) 200; уборка;
  - профиль: данные свои, ссылки Google/webcal содержат свой токен, axe, 360 px.
- **e2e** `tests/e2e/what-if.spec.ts`: Алиса — экзамен «3» → «под угрозой» + причина, «Сбросить» → «сохранится»; Тимур — «под угрозой» из-за долга при любых выборах; закрытый семестр — секции нет; 360 px + axe.
- **e2e** `tests/e2e/pwa.spec.ts` (`serviceWorkers: "allow"`): `/manifest.webmanifest` и `/sw.js` отдаются без входа; визит `/schedule` → дождаться `navigator.serviceWorker.ready` и докачки → `context.setOffline(true)` → перезагрузка `/schedule` и `?week=<следующая>` показывают пары и тост (приёмка 2); `/grades` офлайн → страница «Нет сети»; выход → офлайн `/schedule` не открывается.
- Приёмку 1 («импортируется в Google Calendar и iOS») закрываю частично: тест содержимого + проверка файла валидатором-разбором в юнит-тесте; настоящий импорт — **вы, после VPS**.
- После прогона — запрос «что осталось от тестов» в БД.

## Риски
- `context.setOffline` в Chromium может не распространяться на fetch из воркера — тогда в тесте эмулирую сеть через CDP `Network.emulateNetworkConditions` для воркера; если и так нет — офлайн-проверка руками с записью в журнал.
- Next при сбое RSC-запроса делает обычную навигацию (её и ловит воркер) — проверю офлайн-переход по ссылке дня, не только перезагрузку.
- Кэшированные страницы «сегодня» рендерились вчера — подписи «сегодня/завтра» в них прошлые; честно закрываю временем «обновлено …» в тосте.
