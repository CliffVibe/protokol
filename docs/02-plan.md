## Порядок работы над каждой задачей (цикл)

1. Человек: `/next-task` → Claude читает задачу, задаёт вопросы, предлагает план (plan mode).
2. Человек одобряет план (скриншот плана → `docs/process/screenshots/`).
3. Claude реализует, гоняет тесты.
4. Claude вызывает субагентов-ревьюеров (`security-reviewer`, `ux-reviewer`, `mobile-qa`) по необходимости.
5. Человек проверяет руками на телефоне (это «ручной этап» для отчёта).
6. `/log` → запись в журнал. Коммит. Деплой (`/deploy` или вручную).

## Риски
| Риск | Что делаем |
|---|---|
| Хостинг недоступен из РФ / блокировки | Российский VPS, деплой в день 1, проверка друзьями |
| «Сегодня» в демо пустое через неделю | Сид от текущей даты + ежедневный пересев расписания |
| Жюри «ломает» демо друг другу (все входят под одними аккаунтами) | Ночной полный пересев демо-данных, кнопка «Сбросить демо», вход «Войти как…» |
| Docker Hub недоступен с VPS / `next build` не влезает в 2 ГБ | Зеркало `mirror.gcr.io`; образ собирается в CI → GHCR; swap 2 ГБ |
| ИИ-ассистент недоступен/ключ кончился | Фолбэк на FAQ без ИИ; фича опциональная |
| Агент ломает изоляцию данных | Инварианты в `05-security.md` + e2e-тесты + `security-reviewer` |
| Не хватит материала для отчёта | Журнал и скриншоты — с первого дня, а не в конце |
