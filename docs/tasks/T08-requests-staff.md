# T08. Заявки и кабинет сотрудника

> Перед началом человек включает security-guidance на время задачи (см. `docs/07-tooling.md`).

**Цель:** сценарии 3, 4, 6 — заявка проходит путь от студента до деканата и обратно.

## Студент
- `/requests`: активные / архив; `StatusChip`; пустое состояние с CTA.
- `/requests/new`: каталог типов (пока простой список; мастер «Зачем?» — в T10); динамическая форма из `RequestType.fields` (zod строится на сервере); язык справки.
- `/requests/[number]`: `RequestTimeline`, ожидаемая дата готовности (`slaDays`), комментарии деканата, отмена заявки (пока статус SUBMITTED).
- Номер вида `С-2026-00042`.

## Сотрудник (`/staff`)
- Очередь: фильтры по статусу/факультету/типу, сортировка по сроку, «просрочено» подсвечено.
- Карточка заявки: данные студента (только нужные), смена статуса с комментарием, отклонение с причиной.
- Каждая смена статуса → `RequestEvent` + `Notification` студенту.
- Кнопка «Сбросить демо» (только при `DEMO_MODE=1`) → `db:reset-demo`-логика через Server Action с проверкой роли STAFF.
