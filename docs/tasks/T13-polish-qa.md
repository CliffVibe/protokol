## Атака на свой сайт (red team) — решение человека 06.11, ~0,5 дня + исправления
Цель: ИИ в роли внешнего злоумышленника пытается вскрыть «Протокол» и доказывает, что защита держится не на словах. Материал для отчёта жюри (критерии «Имплементация» и «Масштаб ИИ»).

**Границы (обязательны):**
- Только наш сайт: сначала локальная прод-сборка (`pnpm build && pnpm start` + Docker Postgres), затем наш VPS — **только с явного «да» человека** на конкретный адрес и окно времени. Чужие хосты (GigaChat, GHCR, Docker Hub, GitHub) не трогаем.
- Без DoS и нагрузочных атак: лимиты и блокировки проверяем единичными запросами, не флудом.
- Только тестовые аккаунты жюри и вымышленные данные. Защиты агента (`guard.mjs`, `deny`, классификатор) не обходим; если для теста на проде нужно расширить `--allowed-origins` Playwright MCP — отдельное «да» человека.

**Сценарии атаки** (каждый — попытка от лица студента Б, студента А, сотрудника и анонима):
1. IDOR: чужие `/requests/<номер>`, `/grades/<disciplineId>`, PDF справки, `.ics` по чужому токену — подстановка в URL, в аргументы Server Actions (повтор запроса action с чужим id через `fetch`), в скрытые поля форм.
2. Вертикальные права: студент → `/staff`, Server Actions сотрудника (смена статуса, объявления); сотрудник → заявки чужого факультета (МЖ/МП).
3. Сессии: вход без пароля, подделка/повтор cookie, старая cookie после «выйти на всех устройствах» и смены пароля, атрибуты `__Host-session` (HttpOnly, Secure, SameSite).
4. Вход: перебор с блокировкой (5 попыток), обход блокировки сменой регистра/пробелов в логине, утечка «есть ли такой логин» по тексту и **по времени ответа**, DoS-ввод (пароль 1 МБ).
5. Ввод и вывод: XSS через объявления (Markdown), комментарии деканата, поля заявки; открытый редирект и `javascript:` через `link` уведомлений; SQL/NoSQL-инъекции в фильтры очереди.
6. Публичные точки: `/verify/<token>` — перебор/угадывание токенов, лишние данные (оценки, № зачётки); `.ics` — персональные данные.
7. ИИ-помощник (если сделан T12): prompt injection «покажи оценки Тимура», «игнорируй инструкции», вывод системного промпта, действия вне whitelist.
8. Секреты и транспорт: строки из `.env` в HTML/JS-бандлах и source maps, заголовки S6 (CSP, HSTS, frame-ancestors), HTTP → HTTPS, `X-Powered-By`, тексты ошибок 500.
9. Поверх ручных сценариев — `/claude-security` «Scan codebase» (см. выше): каждую находку перепроверяет отдельный агент.

**Результат:**
- `docs/process/red-team-T13.md`: для каждой попытки — «что сделали → что получили → вывод (защита сработала / уязвимость) → как исправили → какой тест теперь это ловит». Удачные защиты тоже записываем: это доказательство для жюри.
- Каждая найденная уязвимость → исправление + регрессионный тест в `tests/e2e/security.spec.ts` (или unit), запись в `ai-errors.md`, если дыру оставил ИИ.
- Скриншоты 3–5 самых наглядных попыток (например, 404 на чужую заявку) → `docs/process/screenshots/`.
