# 05. Безопасность — инварианты

Этот файл — контракт. Любое изменение кода, нарушающее пункт ниже, — баг уровня «блокер».
Изменять файл — только по явной просьбе человека.

## S1. Студент видит только свои данные
- Идентичность берётся **только из сессии** (`requireStudent()` → `ctx`). Никогда из URL, query, тела запроса, скрытых полей.
- Все запросы к БД — через `src/server/repos/*`, каждый фильтрует по `ctx.studentId` / `ctx.groupIds`.
- Ресурс по номеру/ID из URL ищется как `findFirst({ where: { number, studentId: ctx.studentId } })`. Не найден → `notFound()`.
- Расписание: только группы, в которых студент состоит.
- Server Actions повторно проверяют роль и владение — не доверяем тому, что кнопка была скрыта.
- Сотрудник видит заявки только своих факультетов (`staff.facultyIds`).

- `proxy.ts` (бывший middleware) — только редирект для удобства. Проверка доступа всегда повторяется на сервере.

## S2. Пароли
- argon2id (memoryCost ≥ 19 МБ, timeCost ≥ 2). Никаких открытых паролей, MD5/SHA для паролей.
- Тестовые пароли в сиде — из env (`SEED_PASSWORD_ALISA` и т. п.), не захардкожены в коде.
- Ошибка входа одинаковая для «нет логина» и «неверный пароль»: «Неверный логин или пароль».
- 5 неудачных попыток → блок на 5 минут (`lockedUntil`) + задержка.

## S3. Сессии
- Токен: 32 случайных байта (crypto.randomBytes), в cookie `__Host-session`: `HttpOnly; Secure; SameSite=Lax; Path=/`.
- В БД хранится `sha256(token)`, не сам токен.
- Срок 7 дней, продление при активности. Выход — удаление записи. «Выйти на всех устройствах» — удаление всех сессий пользователя.
- Смена пароля → сброс всех других сессий.

## S4. Секреты
- Только `process.env` на сервере. Запрещён префикс `NEXT_PUBLIC_` для любых ключей.
- `.env*` в `.gitignore`, кроме `.env.example`.
- Перед сдачей: `gitleaks detect` (или `git log -p | grep -i key`) по всей истории.

## S5. Ввод и вывод
- Все входные данные Server Actions и API — zod.
- Никакого `dangerouslySetInnerHTML` с пользовательским вводом. Markdown объявлений — через санитайзер.
- Загрузка файлов (если будет): только PDF/JPG/PNG, ≤ 5 МБ, проверка сигнатуры, хранение вне `public/`.

## S6. Заголовки и транспорт
- HTTPS (Caddy). HSTS.
- CSP: `default-src 'self'`; без inline-скриптов, кроме nonce Next.js.
- `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `frame-ancestors 'none'`.

## S7. Публичные точки
- `/verify/[token]`: токен 128 бит; показываем только «действительна / отозвана / срок истёк», тип справки, дату выдачи, срок действия («действует до») и инициалы («Петрова А. С.»). Никаких оценок, номера зачётки.
- `/api/calendar/[token].ics`: отдельный токен, перевыпускается из профиля; без оценок и персональных данных, только пары.

## S8. ИИ
- В промпт попадают только данные текущего студента. Системный промпт запрещает раскрывать данные других и выполнять действия.
- Ответ модели не исполняется: действия — только как ссылки/кнопки, которые студент нажимает сам, и Server Action проверяет всё заново.
- Лимит: 20 запросов в час на пользователя.

## S9. Данные
- Только вымышленные. Генератор сида не использует реальные списки ФИО преподавателей вуза.

## Обязательные тесты (tests/e2e/security.spec.ts)
1. Студент Б открывает `/requests/<номер заявки А>` → 404.
2. Студент Б вызывает Server Action изменения/отмены заявки А → ошибка, заявка не изменилась.
3. Студент открывает `/staff` → редирект/404.
4. Неавторизованный открывает `/`, `/grades` → редирект на `/login`.
5. В HTML и JS-бандлах нет строк из `.env` (поиск по значению ключа).
6. В БД `passwordHash` начинается с `$argon2id$`.
7. 6 неверных паролей подряд → блокировка.
8. `/verify/<token>` не содержит номера зачётки и оценок.

## Как объяснить жюри простыми словами (для отчёта)
- «Пароль мы не храним — храним его „отпечаток“, из которого пароль не восстановить».
- «После входа браузер получает случайный пропуск, который не может прочитать даже JavaScript на странице».
- «Сервер всегда сам определяет, кто вы, по пропуску — поэтому подменить номер в адресе бесполезно».
- «Ключи от ИИ лежат только на сервере; браузер о них не знает».
