# 01. Концепция — «Протокол»

> Рабочее название. В дипломатии протокол — это правила, по которым всё происходит вовремя и в правильном порядке.
> Наш «Протокол» делает то же самое с учебной жизнью: всё важное — в одном месте и в нужный момент.
> Логотип — собственная монограмма «П» в печати-штампе, без отсылок к гербу МГИМО.

## Проблема

Учебная жизнь студента разбросана:

| Что нужно | Где сейчас | Боль |
|---|---|---|
| Расписание | сайт, PDF, чат старосты | переносы узнаёшь последним; языковые группы — отдельно |
| Оценки | отдельная система | непонятно «как у меня дела в целом», есть ли риск по стипендии |
| Справки | очередь в деканате | надо прийти, непонятно какую справку просить, когда будет готово |
| Объявления | чаты, почта | тонут в шуме, дедлайны теряются |

Гипотеза: студенту нужен не «ещё один сайт с разделами», а **один экран, который отвечает на вопрос «что мне сейчас важно?»**,
и деканат, с которым можно взаимодействовать, как с хорошей службой доставки: заказал → видишь статус → получил.

**Что сказали студенты** (пилотный опрос 06.11, 4 ответа из 4 вузов, не МГИМО — подробно в `docs/process/survey-results.md`):
- расписание и новости смотрят **только с телефона** — 4 из 4;
- о переносах узнают **из чата группы** — 4 из 4; сайт вуза для этого не открывает никто; двое узнают об отмене, уже придя на пару;
- в кабинете первым хотят **главный экран «что мне сейчас важно»** — 3 из 4;
- последняя справка — **справка об обучении**, ждали **неделю**;
- в свободных ответах — «никакого общения не было, только замены, и то через чаты», «отсутствие связи».

Выборка маленькая и не случайная, поэтому это сигналы, а не статистика, — но все они совпали с гипотезой ниже.

## Персоны (вымышленные)

- **Алиса, 2 курс, ФМО.** Два языка, языковые группы не совпадают с основной. Хочет: не пропускать переносы, видеть пары на сегодня одним взглядом с телефона в метро.
- **Тимур, 4 курс, МЭО.** Одна задолженность, едет на стажировку. Хочет: понять, что с долгом и стипендией; быстро получить справку об обучении на английском для визы.
- **Ирина Сергеевна, специалист деканата.** Хочет: очередь заявок, а не поток писем; объявить перенос сразу нужным группам.

## Ключевые сценарии (по ним жюри будет проходить)

1. **Утро.** Войти → главная «Сейчас»: ближайшая пара (аудитория, преподаватель, сколько до начала), подсвеченный перенос, ближайший дедлайн.
2. **Как дела с учёбой.** Успеваемость → средний балл, светофор по дисциплинам, статус сессии, «стипендия: сохраняется / под угрозой».
3. **Справка для визы.** Заявки → «Зачем нужна справка?» → «Для визы/посольства» → система предлагает «Справка об обучении на английском» → отправить → статус «Принята».
4. **Деканат обработал.** Сотрудник в своём кабинете → «В работе» → «Готова» → студент получает уведомление → скачивает PDF с QR.
5. **Проверка подлинности.** Кто угодно сканирует QR → публичная страница «Справка действительна, выдана 05.11.2026» — без лишних персональных данных.
6. **Изоляция.** Студент Б подставляет в адрес ID заявки студента А → 404.

## Разделы

### Обязательное ядро (из брифа)
1. **Вход и профиль** — логин/пароль; ФИО, факультет, направление, курс, группа, языковые группы.
2. **Расписание** — сегодня / неделя; аудитория, корпус, преподаватель; переносы и замены выделены цветом и иконкой; основная + языковые группы в одной ленте.
3. **Успеваемость** — дисциплины, текущий рейтинг (из 100), зачёты/экзамены, сессия, сводка «как дела».
4. **Заявки и справки** — каталог справок, подача, таймлайн статусов, комментарии деканата.
5. **Уведомления** — объявления деканата, напоминания о дедлайнах, изменения расписания, смена статуса заявки.

### Смелые идеи (то, за что дают баллы «проработанности»)

| # | Идея | Приоритет | Почему это меняет опыт |
|---|---|---|---|
| A | **Лента «Сейчас»** — главная, собранная по срочности, а не по разделам | MUST | Отвечает на главный вопрос за 0 касаний |
| B | **Кабинет сотрудника** — очередь заявок, смена статуса, рассылка объявлений группам | MUST | Без него статус заявки — декорация. С ним — живой сценарий от начала до конца |
| C | **Заявка как доставка** — таймлайн, ожидаемый срок, комментарии | MUST | Убирает «зайдите завтра» |
| D | **Мастер «Зачем нужна справка?»** — выбор цели вместо выбора бланка; справки на русском/английском | SHOULD | Студент не обязан знать названия бланков. Для МГИМО — визы и стажировки |
| E | **Справка с QR-проверкой** — PDF + публичная страница проверки | SHOULD | Справку не нужно нести в бумаге; работодатель/посольство проверяет сам |
| F | **Стипендиальный светофор и «Что если…»** — «если сдам экономику на 4 — стипендия сохранится?» | SHOULD | Превращает таблицу оценок в ответ |
| G | **Расписание в свой календарь** (.ics-подписка) + работа офлайн (PWA) | SHOULD | Расписание живёт там, где студент уже смотрит |
| H | **ИИ-помощник деканата** — отвечает на вопросы по регламентам и о своих данных («когда у меня следующий экзамен?», «какую справку взять для военкомата?»), умеет открыть нужный раздел или черновик заявки. Сотруднику — черновик ответа и авто-категория заявки | SHOULD | Деканат 24/7. Ключ ИИ только на сервере, данные — только текущего студента |
| I | **Тёмная тема, крупный шрифт, режим доступности** | COULD | Критерий «Качество» |

Правило отбора: сначала ядро + A, B, C работают идеально и на 360px. Только потом D–I.

#### Кандидаты из ресерча 11.11 (T14) — J, K реализованы 11.11 (выбор человека), N у студента снята, L и M — «что дальше»
Подробно, с источниками — `docs/process/research-ideas-T14.md` (19 идей из реальных вузов и сервисов: Georgia State, Leeds, Edinburgh, UNSW, Госуслуги, Эстония…).

| # | Идея | Оценка | Почему меняет опыт |
|---|---|---|---|
| J | **«Вам положено»** — деканат сам предлагает повышенную стипендию или матпомощь по данным студента, подтвердить в 1 касание | M | Общение разворачивается: деканат приходит к студенту, а не ждёт заявления (беззаявительные услуги) |
| K | **Оценка решения заявки + «Вы сказали — мы сделали»** | S | Общение становится двусторонним; у сотрудника — метрика качества рядом со сроками |
| L | **«Я заболел»** — самосертификация короткого пропуска (только даты, лимит) | M | Деканат доверяет студенту; не нужно идти за справкой ради двух дней |
| M | **Электронный студенческий с QR-проверкой** | S–M | Повестка 539-ФЗ (электронные студбилеты); переиспользует страницу проверки справки |
| N | ~~**«Свободные аудитории сейчас»** — для окна между парами~~ — **у студента снято 11.11** (решение человека: свободные аудитории обычно закрыты, ключи студентам никто не даст — подсказка обещала бы то, чего нет). Механизм переехал к сотруднику: при переносе пары сервер ловит накладки (группа, языковые пары студентов, преподаватель, аудитория) и подсказывает свободные аудитории корпуса | S | У студента — повод открывать кабинет; у сотрудника — перенос без звонков «а эта аудитория свободна?» |
#### Деканату (ресерч 11.11, T14+) — три сделаны 12.11 (выбор человека «Брифинг + пакет + база»)
Подробно, 16 идей с источниками — `docs/process/research-dean-office-T14.md`. Цель — сотрудник занимается исключениями, а не рутиной.

| Идея | Что у Ирины | Откуда |
|---|---|---|
| **Утренний брифинг** | первый экран дня: «горят» (просрочены и срок сегодня — словами), «готовы — выдать пачкой», «новые со вчера», «ответы ждут проверки»; каждый пункт — ссылка на отфильтрованную очередь | дашборд советника Salesforce Student Success |
| **Пакетная обработка с шаблонами** | выбрать «Подана» (N) / «Готова к выдаче» (N) → один шаг вперёд и один шаблон ответа на всех; текст для каждой заявки (справка, срок, часы выдачи) собирает сервер; отклонять пачкой нельзя | макросы Zendesk, массовые операции Workday Student |
| **База знаний из заявок → помощник** | «Сделать ответом помощника» из ответа на заявку → сервер убирает имя, номера, контакты → Ирина правит и публикует → ИИ-помощник отвечает этим всем студентам с подписью «Ответ деканата от …» | University of South Dakota (TeamDynamix), University of Houston |

Дальше (в отчёт): кампании и сигналы «нужна помощь», автовыдача типовых справок, массовый перенос пар заболевшего преподавателя, конструктор правил «Вам положено».

«Главное — не количество разделов, а то, насколько продуманно они работают вместе» (из брифа).

## Правило стипендии (вымышленное)
Для прототипа — **не правила МГИМО**, а понятное правило, на котором видно «как у меня дела» (T05, расчёт — `src/server/services/academics.ts`, тот же код в T07). Стипендия сохраняется, если:
1. нет долгов ни в одном прошлом семестре (оценка 2 или «не зачтено»);
2. в прошлой сессии нет оценок ниже 4;
3. в текущем семестре рейтинг по каждой дисциплине не ниже 60 из 100.

Иначе — с причинами («Долг: Эконометрика», «Международные финансы: 54 из 100, нужно 60») и одним из двух статусов (T14, после оценки «глазами жюри»): нарушены пункты 1–2 (долг, тройка в прошлой сессии) — **«стипендия не назначена»**, это уже факт; только пункт 3 (рейтинг) — **«под угрозой»**, ещё можно исправить. Нет ни одной оценки (первокурсник до сессии) — статуса нет.

**Светофор дисциплины** (T07, тоже вымышленный, из того же правила): «Долг» — оценка 2 или «не зачтено»; «Ниже 60» — текущий рейтинг ниже 60 из 100 (с подсказкой, сколько баллов не хватает); «Оценка 3» — тройка; остальное — «в норме» или итог словом. Расчёт — `src/server/services/academics.ts` (`gradeAttention`), им же воспользуется «Что если…» (T11).

## Было → стало (в цифрах)

Касания считаем от главной «Сейчас». «Было» — по пилотному опросу (`docs/process/survey-results.md`); строки, которые ещё не закрыты задачами, помечены.

| Сценарий | Было (по опросу) | Стало в «Протоколе» |
|---|---|---|
| Узнать о переносе пары | из чата группы (4 из 4); двое — «прихожу и узнаю на месте» | 0 касаний — подсвечено на «Сейчас» + уведомление (T05, T09) |
| Понять, сохранится ли стипендия | понятность 1, 3, 5, 5 из 5 — у одного «совсем непонятно» | 0 касаний — значок стипендии на «Сейчас», причины — 1 касание («Учёба», T07); «если сдам на 3 — сохранится?» — 3 касания: «Учёба» → «Что если сдать сессию…» → оценка, ответ сразу (T11) |
| Заказать справку для визы | визит в деканат, справку об обучении ждали неделю | 5 касаний: «Заявки» → «Заказать справку» → «Виза» → справка на английском → «Отправить заявку»; статус онлайн, срок 3 рабочих дня, PDF с QR — сразу на «Готова» (T08, T10) |
| Проверить подлинность справки | звонок в деканат | скан QR камерой, без входа: «Действительна / Отозвана» и срок действия (T10) |
| Посмотреть расписание без сети (метро, корпус в Одинцове) | расписание смотрят с телефона (4 из 4); офлайн в опросе не спрашивали | 1 касание без сети — две недели сохраняются после первого визита, плашка «показываем сохранённое, обновлено …» (T11) |
| Расписание в своём календаре | в приоритетах — 0 из 4 (честно: студенты этого не просили) | 3 касания один раз: «Ещё» → «Профиль» → «Добавить в Google Календарь» / «на iPhone»; дальше переносы приходят в календарь сами (T11) |

## Адаптация под МГИМО

- Факультеты и институты в сиде: ФМО, МП, МЭО, МЖ, ФУП, ФМБ, МИЭП, ИМТУР (открытые названия).
- **Языковые группы** — отдельная сущность; пары по языку идут в общем расписании, но с меткой языка.
- Корпуса: «Главный корпус (пр-т Вернадского)», «Одинцово» — с подсказкой, сколько времени на переход, если пары в разных корпусах подряд.
- Типовые справки: об обучении (рус./англ.), для военкомата, в соцзащиту, для посольства/визы, о стипендии, академическая справка; заявления: на стажировку/мобильность, на пересдачу, на академический отпуск.
- Оценки: рейтинг из 100 → итоговая оценка по 5-балльной шкале / «зачтено». *Допущение для прототипа; реальные правила вуза не воспроизводим.*

## Не цели

- Не заменяем LMS (материалы курсов, домашки) — только ссылкой.
- Не делаем мессенджер. Связь с деканатом — через заявки и комментарии к ним.
- Не интегрируемся с реальными системами вуза.
